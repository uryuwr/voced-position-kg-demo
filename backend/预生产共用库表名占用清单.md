## 为什么必须先对表名

本项目没有 migration 框架，靠启动时 `ensure_*_schema()` 的幂等 DDL 演进表结构，全是 `CREATE TABLE IF NOT EXISTS`。

**撞名不会报错，会静默跳过**，然后本项目拿着别人的表结构跑 —— 症状是「列不存在」「类型不对」，而且只在共用库里复现，本地怎么都查不出来。这是本清单存在的唯一理由。

## 建表约定

1. **一律带前缀**：图数据 `kg_`，业务数据 `biz_`。禁止 `users`、`sessions`、`events`、`nodes`、`edges` 这类裸名 —— 共用库里迟早撞。
2. **新表先查占用**：连上库跑下面的 SQL，确认目标名没被用。
3. **别碰不属于本项目的表**：`checkpoint_*` / `conversation_*` / `knowledge_*` / `app_runtime_config` 都是 bcs-ai-agent 的，只读都不要读。
4. 如果将来要彻底隔离，正解是给本项目建独立 **schema**（`CREATE SCHEMA voced; SET search_path`），靠前缀只是约定，挡不住手误。

## 核对当前占用

```sql
-- 全部表 + 归属判断
SELECT tablename,
       CASE WHEN tablename LIKE 'kg\_%' OR tablename LIKE 'biz\_%' THEN '本项目'
            ELSE '其它项目' END AS owner
FROM pg_tables
WHERE schemaname = 'public'
ORDER BY owner, tablename;

-- 建新表前查单个名字（返回有行 = 已被占用，换名）
```
