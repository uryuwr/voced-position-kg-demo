# 知识图谱重构总方案（模型 + 边定义 + 旧数据清洗 + 接口 + 前端）

> 整合并统领：`docs/系统架构问题与优化-能力全景.md`（模型/接口/前端）与 `docs/边关系规则对比与整改.md`（边语义/清洗）。
> 目标：从「通用图探索器」→「能力体系结构化全景」；一次把**数据模型、边定义、旧数据清洗**对齐到位，再改接口与前端。

## 一、终态目标

- 图谱默认回答三问：**行业/专业下有哪些岗位 → 岗位怎么晋升 → 每岗位要哪些技能到什么等级**。
- 三层结构清晰可分层渲染：**归属树 contain(1:N) / 关联网 require·associate(N:M) / 进阶链 progress(1:1)**。
- 每条边**单一语义、方向统一、带 structure_layer 标签、可溯源**；`related_to` 不再当万能边。

## 二、边定义终稿（重构后）

| 结构层 | rel_type | 方向(src→dst) | 语义 | 说明 |
| --- | --- | --- | --- | --- |
| tree | `contain` | industry→major→occupation | 归属（1:N，父→子） | 统一归属树；替代 belongs_to 的归属职责 |
| net | `prepares_for` | major→occupation | 专业对口岗位 | 只保留"对口"关联语义 |
| net | `requires` | occupation→skill_level | 岗位要求技能 | 保留 |
| net | `covers` | major→skill_level | 专业培养技能 | **需补建**（现 0） |
| net | `taught_by` | skill_level→course | 技能由课程习得 | related_to(course→skill) 翻转迁入 |
| net | `recognized_by` | occupation→credential | 岗位认可认证 | related_to(occ→cred) 迁入 |
| net | `articulates_to` | major→credential | 专业衔接认证 | related_to(major→cred) 迁入 |
| net | `offers_course` | major→course | 专业开设课程 | **新增类型**；related_to(major→course) 迁入 |
| chain | `advances_to` | occupation→occupation | 岗位晋升（同族 level 递进） | **新增类型 + 新增数据** |
| chain | `skill_progress` | skill_level→skill_level | 技能等级递进 L→L | 可选；skill 合并重构后再建 |
| net | `related_to` | *↔* | 弱相关（同层，如岗↔岗/技↔技/课↔课） | 仅保留真正的同层弱关联 |
| — | `parent_of` | industry→industry | 行业父子 | 归入 tree；建议统一为 contain 或保留 |
| — | `same_as` | *↔* | 跨库等价 | 技术去重边，不进业务视图 |

命名口径：**不物理重命名已用 rel_type**（避免动 API/前端全链路）；规则总表的 HAS_OCCUPATION/REQUIRES_SKILL/… 作为业务 label 映射到上表 rel_type。

## 三、旧数据清洗清单（现状 → 目标）

| # | 现状 | 目标 | 量级 | 可逆 |

| D1 | `related_to` course→skill_level | 翻转为 `taught_by` skill_level→course | 7350 | 是 |
| D2 | `related_to` occupation→credential | 改类型 `recognized_by` | 2042 | 是 |

清洗原则：**保留原 evidence/source/confidence**；迁移前按 confidence 抽检（大量应为 ai_inferred/derived，低置信需人工确认）；每步先 `SELECT count` 预演、再 `UPDATE`、后校验；全程可回滚（备份 + 软标记）。

## 四、执行顺序（含依赖，↓ 表示前置依赖）

### S0 · 冻结与备份（前置一切）
- 备份 `kg_node` / `kg_edge`（pg_dump 或建 `*_bak_20260807` 表）。
- 暂停/加锁写边的采集脚本（`crawlers/pipelines` 里 link_* / ingest_*），避免清洗期间按旧语义继续写入。

### S1 · Schema/字段定稿（↓S0）——先定型再动数据
- S1.1 DDL：`kg_node` 加 `level int`（occupation 用）、`category text/jsonb`（skill 用）。
- S1.2 建/登记新 rel_type：`offers_course`、`advances_to`（+ 可选 `skill_progress`、`related_course`）；给 `kg_edge` 加 `structure_layer` 列（tree/net/chain）。
- S1.3 定稿"业务 label ↔ rel_type"映射表（写入 `schemas/graph_schema.yaml` 与 openapi 文档）。

### S2 · 边语义化迁移 + 归属树理顺（↓S1）
- 顺序：D1→D2→D3→D4→D5（related_to 拆分）→ D6（建 contain）→ D11（打 structure_layer）。
- 每项：预演 count → UPDATE（改 rel_type/翻转 src/dst）→ 校验（原 related_to 该子集归零、新类型计数吻合）。

### S3 · 补齐派生/属性数据（↓S2）
- D7 covers（专业→技能，派生补建）。
- D10 skill.category 回填（先规则/映射，缺的人工）。
- D9 occupation.level 回填（职级来源/推导/人工）。

### S4 · 进阶链（晋升）（↓S3，依赖 occupation.level）
- 建 `advances_to`（同专业/岗位族内按 level 递进，1:1 有向）。
- （可选）skill 合并重构（skill_level→skill+level）后建 `skill_progress`——**大改，排最后或单列**。

### S5 · 接口层（↓S2/S3/S4，依赖干净数据）
- 新增能力全景聚合接口 `GET /v1/capability?industry=|major=`：归属树(contain) + 岗位晋升(advances_to/level) + 岗位-技能矩阵(requires，带 category + 共享度)。对齐 `knowledgeGraph.json`。
- 现有图接口响应补 `structure_layer` 与技能共享度字段。
- 读路径统一只返回 `published`（校验 explore/expand/capability 都过滤）。

### S6 · 前端（↓S5）
- 默认视图改「分层树 + 晋升链」，技能层默认折叠（L4）。
- 技能层渐进展开：悬停岗位展开 requires；焦点过滤；**高频共享技能提取到侧栏、按 category 分组、不画线**。
- 力导向降级为「关联网探索」可选项。

### S7 · 验收/回归（↓S6）
- 数据：无残留错位 related_to；covers/advances_to 计数与连通性；每边有 structure_layer。
- 读路径：前台/图/学员端仅 published；能力全景接口三层齐全。
- 可读性：默认视图边数从 ~85 降到 ~28；共享技能不再星形汇聚。

## 五、里程碑与优先级

- **里程碑 A（数据地基，P0）**：S0 → S1 → S2 → S3 → S4(不含 skill 合并)。产出：边语义干净、有 level/category、有晋升链。**不完成 A，接口和前端都做不出"晋升/能力全景"。**
- **里程碑 B（能力全景可用，P1）**：S5 → S6。产出：`/v1/capability` + 分层树前端，默认可读。
- **里程碑 C（增强，P2）**：skill_level→skill+level 合并重构、skill_progress、关联网高级探索、认证恢复发布。

## 六、风险与回滚

- 每阶段前备份、迁移可逆（rel_type/方向改动保留旧值到 attrs.migrated_from）；出错可反向 UPDATE。
- 命名不物理改，降低 API/前端联动风险。
- skill 合并重构影响所有引用 skill_level 的边 → 单独里程碑 C、充分回归后再做。
