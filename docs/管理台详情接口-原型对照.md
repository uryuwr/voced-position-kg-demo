# 管理台四维详情接口 · 原型对照

原型：`backend.html`（Open-Q 管理端交互原型）。用真实浏览器抓取渲染后 DOM 得到实际字段，
非凭截图推测。原型里只有**专业**有「详情」抽屉、**岗位**有「技能构成」抽屉；
行业与技能仅有列表，无详情面板——但按需求要补齐四类详情接口，
行业/技能的详情内容依据其列表列 + 图谱可得数据设计。

## 一、原型列表列（四类）

| 类型 | 列 |
| --- | --- |
| 行业管理 | 行业名称、**编码**、状态、关联专业、关联岗位、操作 |
| 专业管理 | 专业、状态、版本、岗位数、基础技能、操作 |
| 岗位模型 | 岗位、所属行业、层级、状态、技能项、权重和、操作 |
| 技能库 | 技能、分类、状态、版本、负责人、等级完整度、操作 |

## 二、专业详情（原型「专业详情 · 电商运营」）

```
头部：行业 | 状态 | 版本 | 简介
关联岗位（4）                                   [+ 添加岗位]
  内容运营专员  已发布
  初级 · 6–10K · 5 项技能 · 权重和 1.00
  ...
聚合技能（13）                                  [按被引用次数排序]
  跨部门沟通  L4
  内容运营专员 L2、商品运营 L3、高级直播运营 L3、电商运营总监 L4
  ...
```

要点：
- 关联岗位每行：名称 + 状态 + `职级 · 薪资 · N 项技能 · 权重和`
- 聚合技能每行：技能名 + **该专业内的最高要求等级** + 引用它的岗位及各自等级
- 聚合技能按**被引用次数**倒序（引用越多越靠前）

## 三、岗位详情（原型「岗位模型 · 内容运营专员」）

```
头部：所属行业 | 关联专业 | 职级 | 薪资 | 状态
技能构成（5）    权重和 1.00
  内容脚本策划   无先修            L1 L2 L3 L4 L5
  短视频剪辑     先修 内容脚本策划   L1 L2 L3 L4 L5
  ...
```

要点：每项技能显示**先修技能**（无则「无先修」）与 L1–L5 档位（高亮到要求等级）。

## 四、接口设计（挂「管理台 · 数据列表」组）

统一 `GET /v1/kg/nodes/{node_id:path}/detail`，按 type 返回对应结构；
也提供 query 版 `GET /v1/kg/node-detail?id=`（id 含冒号时用，与既有 `/v1/node` 一致）。

| type | 返回段 |
| --- | --- |
| industry | `majors[]`（专业+岗位数）、`occupations[]`（直连岗位）、`counts` |
| major | `industries[]`、`occupations[]`（含 level/salary/skill_count/weight_sum）、`aggregated_skills[]`（含 required_level 与 used_by[]，按引用数倒序） |
| occupation | `industries[]`、`majors[]`、`skills[]`（含 required_level/weight/levels/prereqs）、`weight_sum` |
| skill_level | `levels[]`（L1–L5 完整度）、`occupations[]`（引用岗位）、`prereqs[]`/`unlocks[]`、`category` |

公共头部：`node`（含 code/status/created_at）、`counts`、`meta`。
