# 五维知识图谱执行计划

> 任务：用 AI + 合法数据采集，生成「专业 → 岗位 → 技能等级 → 课程 → 认证」五维关联图谱  
> 三张图谱：**国内**、**欧盟**、**美国**  
> 依据：`需求.md` + `docs/AI职业教育toC方案.md` + `docs/中高等职业教育AI赋能解决方案.md` + 现有样例 `AI能力知识图谱可视化.html`

---

## 0. 先把思路理顺（一页纸）

你现在乱，本质是三个问题搅在一起：

| 问题 | 一句话答案 |
| --- | --- |
| 照着旧数据走，还是重来？ | **骨架用官方公开数据重采（带出处）**；旧数据只作「对照样本 / 字段参考」，不直接当真源 |
| 要不要大规模爬虫？ | **尽量不爬**。美/欧有官方批量下载与 API；国内优先教育部/人社部公开目录与官方 PDF。爬虫只作最后手段，且只碰允许抓取的页面 |
| 三张图怎么并行？ | **同一套本体（schema）+ 三套区域数据管道**；先打通 1 个垂直域 MVP（如 IT/AI），再全量扩 |

核心原则：

1. **数据可溯源** > 数据量：每条节点/边必须有 `source_id + source_url + license + fetched_at`
2. **官方批量下载 / API** > 页面爬取 > 人工 PDF 抽取
3. **关联边分两档**：官方已有映射（高置信） vs AI 推断映射（低置信，需标注 + 可人工审）
4. **合规红线**：遵守 robots.txt、ToS、许可证；限速；不绕过登录/验证码；不碰个人隐私与封闭商业库

## 1. 目标定义（做成什么样算完成）

### 1.1 五维实体

| 维度 | 含义 | 典型例子 |
| --- | --- | --- |
| 专业 Major | 学历教育专业目录节点 | 中国高职「软件技术」、本科「计算机科学与技术」 |
| 岗位 Occupation | 职业/岗位分类节点 | O\*NET `15-1252.00`、ESCO occupation、人社部职业细类 |
| 技能等级 SkillLevel | 技能 + 等级（不是裸技能名） | 「Python · L2」「机器学习 · L3」；或 O\*NET Importance/Level |
| 课程 Course | 可学习的课程/模块 | 公开课、MOOC、职业院校课标课程（有链接） |
| 认证 Credential | 证书/资格 | 1+X、人社部证书、CompTIA、AWS、欧盟相关资格 |

### 1.2 核心关系（边）

```
专业  --培养/对口-->  岗位
岗位  --要求-->      技能等级
专业  --覆盖-->      技能等级
技能等级 --由...习得--> 课程
课程  --通向-->      认证
岗位  --认可-->      认证
专业  --衔接-->      认证（岗课赛证）
```

每条边至少：`relation_type`、`confidence`（official | derived | ai_inferred）、`evidence`、`source_url`。

### 1.3 三张图的边界

| 图谱 | 专业轴 | 岗位/技能轴 | 课程/认证轴（优先） |
| --- | --- | --- | --- |
| **美国** | CIP / 职业相关专业目录（与 O\*NET 教育要求衔接） | **O\*NET** 职业 + 技能矩阵 + 等级 | CareerOneStop、公开认证目录、可公开访问的课程元数据 |
| **欧盟** | 各国/EQF 相关专业与资格框架 | **ESCO** 职业 + 技能 + 关系 | Europass / 公开 VET 课程与资格（按许可证） |
| **国内** | 教育部中职/高职/本科/研究生专业目录 | 人社部职业分类 +（可选）对接国际职业编码 | 1+X、职业资格/技能等级证书、公开课/职教课标（公开源） |

文档中已有数量级可作「完成度标尺」（非必须一次打满）：

- 专业 ~2082（四层次）
- 职业 ~5368（O\*NET + ESCO + ISCO 汇总口径）
- 技能矩阵 ~62580 行（O\*NET）
- 技能等级样例：15 核心技能 × L1–L4
- 课程关联 5800+（外部）

**第一阶段不要求全量**，要求「链路通 + 可溯源 + 可查询」。

## 2. 旧数据怎么用？（关键决策）

### 2.1 现状判断

| 已有资产 | 价值 | 风险 |
| --- | --- | --- |
| 飞书方案里的指标与数据源清单 | 方向正确：O\*NET / ESCO / ISCO / 教育部目录 | 无库文件、无出处链接 |
| `AI能力知识图谱可视化.html` | 五维交互 demo、字段样例、IT/AI 垂直样例 | 手工样例，无 source；维度是「薪资」不是「认证」 |
| 待补齐清单（ESCO 技能 CSV、人社部 PDF、薪酬） | 明确缺口 | 说明旧工程未完成 provenance |

### 2.2 决策（推荐）

**不要「盲信旧库直接扩」；也不要「全部扔掉从零空想」。**

采用 **双轨**：

```
轨 A · 权威底座（必须）     官方下载/API → 规范化 → 带 source 入库
轨 B · 旧数据/样例（辅助）  仅用于：字段对照、覆盖率比对、边类型设计、demo 迁移
```

| 场景 | 做法 |
| --- | --- |
| O\*NET / ESCO 实体与官方关系 | **重采**官方包（这些本来就有公开下载，旧数据无链接就重下） |
| 国内专业目录、人社部职业 | **重采**官方最新版；旧名单可 diff 看是否漏 |
| 专业↔岗位、技能↔课程 等推断边 | 旧边若无证据 → **不继承**；用规则 + AI 重算并标 `ai_inferred` |
| HTML 里 IT/AI 样例 | 迁移为 MVP 种子图（补 source 或标 `manual_seed`） |

**结论：从头建立「可溯源流水线」；旧内容当蓝图与验收对照，不当无出处的真理。**

## 3. 合规采集策略（必须遵守）

### 3.1 优先级（从合法到慎用）

1. **官方批量数据 / 开放 API**（首选）  
   - 美国：O\*NET Database / Web Services（遵守其 Terms of Service）  
   - 欧盟：ESCO 官方下载（CSV/XML）与 API（注意许可证，一般为开放但需署名）  
   - 国际：ISCO-08 结构（ILO 相关公开材料）  
   - 国内：教育部专业目录公开页面/文件、人社部职业分类大典公开材料  
2. **官方允许的检索/开放目录**（有 robots 与 ToS 时遵守）  
3. **人工下载公开 PDF + OCR/解析**（人社部细类、课标等；注意版权仅用于内部知识图谱、不二次散播全文）  
4. **站点爬虫**（最后手段）：  
   - 先读 robots.txt 与用户协议  
   - 仅公开页；限速；缓存；带 User-Agent 与联系方式  
   - **禁止**：绕过登录、验证码、付费墙；批量抓取禁止爬的商业招聘站/课程站全文  

### 3.2 明确不做

- 不爬需登录才能看的课程正文、试题、封闭题库  
- 不爬个人隐私、简历、未授权企业内训材料  
- 不用「反爬对抗」思路（代理池打码等）换数据  

### 3.3 每条数据强制 provenance

```yaml
entity_or_edge:
  id: ...
  region: CN | EU | US
  source_system: ONET | ESCO | MOE_CN | MOHRSS_CN | ...
  source_id: "15-1252.00"   # 源系统主键
  source_url: "https://..."
  license: "CC-BY-4.0 / O*NET Terms / ..."
  fetched_at: "2026-..."
  confidence: official | derived | ai_inferred | manual_seed
```

## 4. 本体与存储（三图共用）

### 4.1 最小 schema（建议）

**节点表 `nodes`**

- `id`, `region`, `type` (major|occupation|skill_level|course|credential)
- `name_zh`, `name_en`, `aliases[]`
- `attrs` (JSON：代码、层次、描述、EQF 等级等)
- provenance 字段同上

**边表 `edges`**

- `src_id`, `dst_id`, `rel_type`
- `weight` / `level` / `importance`（可空）
- provenance + `confidence` + `evidence`（短文本或规则名）

**可选：映射表 `crosswalk`**

- 中/欧/美职业编码互映射（ISCO 作枢纽）

### 4.2 技术选型（务实）

| 层级 | 建议 | 说明 |
| --- | --- | --- |
| 原始层 | `data/raw/{region}/{source}/` | 原样保存官方包 + 校验和 |
| 清洗层 | `data/staging/` parquet/csv | 统一字段 |
| 图谱层 | 先 SQLite / PostgreSQL + 边表；需要再上 Neo4j | MVP 不必一上来图数据库 |
| 编排 | Python + 可复现脚本 | 每源一个 `ingest_*.py` |
| AI | 仅用于：对齐、摘要、推断边、等级描述 | 输出必须可回放、可抽检 |

## 6. AI 用在哪（物流代码 vs 语义）

符合你们一贯原则：**LLM 做语义判断；知识库/DSL 提供证据；代码做路由与落库。**

| 步骤 | 谁做 | 说明 |
| --- | --- | --- |
| 下载、解析、校验、去重 | 代码 | 可复现 |
| 官方已有边 | 代码直写 | `confidence=official` |
| 中英名对齐、同义归并 | AI + 规则 | 输出候选 + 人工抽检规则 |
| 专业→岗位（无官方边时） | AI 推断 | 强制引用专业描述/就业方向文本；低置信入库 |
| 技能→课程 / 课程→认证 | AI 推断 + 白名单课程库 | 禁止无链接课程 |
| 质量巡检 | AI + 统计 | 断链、环、孤立点、冲突等级 |

**禁止：** 用 AI「编造」不存在的官方代码或证书编号。

## 8. MVP 范围建议（避免一上来全宇宙）

**第一刀（强烈建议）：**

- 区域：先 **US（O\*NET）+ 国内 IT/AI 试点**  
- 维度：五维都要有样例，但 **岗位–技能等级** 必须最硬  
- 规模：国内试点 **10 专业 × 20 岗位 × 30 技能 × 4 等级 × 50 课程 × 20 认证** 跑通闭环  
- 再复制到欧盟 ESCO，再扩国内全专业目录  

与业务文档的对应：

- toC：诊断 → 路径 → 匹配课程 → 认证  
- toB 院校：产业-人才 Gap、岗位→课标、岗课赛证

## 10. 风险与对策
