# 8.20 完整任务目标 vs 当前缺口

> **纠偏：** 此前大量「IT 试点 / 种子 / 先通链路」是 **路径策略**，不是最终目标。  
> **最终目标**以 `docs/五维知识图谱执行计划.md` + `docs/CN五维数据获取计划.md` 的 **完整齐** 为准。  
> 产品用途：可溯源的 **专业→岗位→技能等级→课程→认证** 图谱（CN/EU/US），不是 Demo。

---

## 1. 完整目标（做成什么样算完成）

### 1.1 三区五维（执行计划 §1）

| 区 | 专业 | 岗位 | 技能等级 | 课程 | 认证 |
| --- | --- | --- | --- | --- | --- |
| **CN** | 中职+高职专科+职业本科+**普通本科**目录 | 大典细类 | 国家职业（技术）技能标准 **规模化** | 职教课标课程 **规模化** | 1+X 主名单等 |
| **EU** | **VET / EQF 职业资格**侧专业与培养入口（非全欧文理专业百科） | **ESCO** 职业（底库+VET 向主路径） | ESCO 技能及官方关系 | 公开 **VET** 课/模块（有 URL） | 职业资格 / Europass 可挂公开项 |
| **US** | **CTE 相关 CIP** + 职业导向项目（非全量文理百科） | **O\*NET** 职业（底库+CTE 向主路径） | O\*NET 技能+等级 | 公开 CTE/社区学院等课元数据 | 行业认证等公开目录 |

### 1.2 主链边（要能走通，且主体可溯源）

```
专业 --prepares_for--> 岗位 --requires--> 技能等级
专业 --covers--> 技能等级（有依据时）
技能 --taught_by--> 课程（有依据时）
课程/岗位/专业 -- 认证相关边 --
```

- 边：`confidence` + `evidence` + `source_url`  
- **完整齐**：主链关系以 `official|derived` 为主体，AI 边可控  

### 1.3 中国「完整齐」定义（CN 计划 §6）

- 专业四层次覆盖  
- 大典细类覆盖  
- **技能标准规模化**（不是 2 个工种）  
- **1+X 主名单**  
- **课标课程规模化**（不是 6 个专业）  
- 主链关系齐全、可查询、Admin 可用  

**口径（已确认）：** 普通本科 + 高职等都算专业侧；岗位大典底库可全，推荐/主路径靠证据边过滤。

---

## 3. 为什么会变成「试点话术」

| 原因 | 结果 |
| --- | --- |
| 官方无「专→岗」全表，连边难 | 用 IT 种子 **启动**，却没切换到规模化计划 |
| 技能/课标是海量 PDF | 先做 2/6 份 **验证解析器**，却把验证当成交付 |
| 执行计划写过「先 MVP 再扩」 | **扩量阶段被拖住**，未按 8.20 完整齐排期 |

**正确用法：** 小样本只验证管道；**交付物必须是规模化节点/边 + 覆盖率报表**。

## 4. 到 8.20 的完整交付清单（按优先级）

### P0 · 中国技能规模化（最大缺口）

- 建立「已颁布国家职业技能标准 / 职业技术技能标准」**目录清单**（可公开拿到的尽量全）  
- **批量下载 + 解析入库**（权重表/工作要求 → skill_level + requires）  
- 与大典岗位 **按代码/名称对齐**（含 2022 大典与旧码映射）  
- 验收：CN `skill_level` 与 `requires` **数量级从「十」到「百～千」**，覆盖主要技术技能大类  

### P0 · 中国课标课程规模化

- 教育部 2025 课标门户：**中职 / 高职专科 / 职业本科** 能下的 PDF **按类批量拉取**  
- 统一解析：课程设置 + 职业面向代码  
- 验收：course 节点与专→课边覆盖 **大部分已发布课标专业**（目标对齐「758 项」量级中可下载部分，能下尽下）  

### P0 · 专→岗规模化（主路径）

- **优先用课标「职业面向」官方代码**（official）批量建 `prepares_for`  
- 补充专业简介/就业面向文本 + 规则/AI 候选 + **抽检表**（derived）  
- 验收：职教+应用向专业 **大部分有 ≥1 条 prepares_for**；Admin 默认可走「有边岗位」  

### P1 · 主链补边

- covers / taught_by / 认证衔接：有课标与 1+X 字段则建  
- Admin：默认过滤 `recommend_tier`、展示 source  

### P0 · 美欧也必须「职教相关完整齐」（已确认）

口径见 `docs/职业教育数据范围.md` §2–3（**EU=VET，US=CTE**）。

| 区 | 必须补到完整齐 | 现状问题 |
| --- | --- | --- |
| **EU** | VET 向 major + course + credential；ESCO 岗技主路径标签/过滤 | 现有 ESCO 偏全劳动力市场；专/课/证弱 |
| **US** | CTE/CIP 向 major + course + credential；O\*NET 岗技主路径标签/过滤 | 现有 O\*NET 偏全劳动力市场；专/课/证弱 |

### P1 · 质检

- 覆盖率报表：**CN / EU / US × 五维** 节点数、边数、official 占比  
- 断链、孤立专业、无 source 课程扫描  
- 主路径是否误推弱相关岗位（保安类推 CN 逻辑）

## 5. 工作方式调整（从现在起）

1. **不再以「试点交付」收口**；小样本只叫 **管道冒烟**。  
2. 每个 Phase 结束要有：**规模化数字** + `reports/*.json` 覆盖率（三区都要）。  
3. 下载/解析 **并行批量**；CN 课标/技能标准、EU VET 公开源、US CIP/CTE/认证目录同步排期。  
4. **三区统一约束：只做职业教育相关（CN 职教+普本口径 / EU VET / US CTE），不是全职业全学科百科。**

---

## 6. 建议开工顺序（完整目标）

```
并行 P0：
  CN  课标批量 + 技能标准批量 + 课标职业代码→prepares_for
  EU  ESCO 主路径标签 + VET 专业/资格/课公开源
  US  O*NET 主路径标签 + CIP(CTE)/认证公开源
→ 主链边规模化与质检报表
→ Admin 默认主路径过滤
```
