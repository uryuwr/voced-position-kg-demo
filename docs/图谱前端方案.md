# 独立图谱前端方案（面向非技术用户）

> 目标：用户**不用写 Cypher / 不用看 Neo4j Browser 英文界面**，用搜索 + 点选即可查看「专业 → 岗位 → 技能 → 课程 → 认证」子图。  
> 现状后端：Neo4j + 已有 API（`/v1/graph/by-major`、`/v1/search`、`/v1/stats`）。  
> 调研日期：2026-08

---

## 1. 问题定义

| 现状痛点 | 目标体验 |
| --- | --- |
| Neo4j Browser 全英文、要写代码 | 中文界面、搜索框 + 按钮 |
| 一次加载 7 万边会卡死 | 按专业/关键字拉**子图**，限深限宽 |
| 开发者工具气质 | 业务产品气质：查专业、看路径、看详情 |

**一句话产品定位：**  
「职业教育知识图谱浏览器」——输入专业名（或选热门专业），自动画出关联图谱；点节点看详情与来源。

---

## 2. 业界类似实现（调研摘要）

### 2.1 可参考的产品形态

| 案例 | 类型 | 用户怎么用 | 对咱们的启发 |
| --- | --- | --- | --- |
| [Neo4j Bloom](https://neo4j.com/product/bloom/) | 商业探索工具 | 自然语言/搜索探索，**不用写 Cypher** | 交互范式：搜索 → 展开邻居 → 样式按类型 |
| [AWS graph-explorer](https://github.com/aws/graph-explorer) | 开源 React 探索器 | 搜索节点、可视化、点开邻居，无查询语言 | 开源可参考；偏通用图库，**偏重、英文、需对接协议** |
| Neo4j LLM Knowledge Graph Builder 前端 | 开源实践 | 上传文档建图 + NVL 可视化 + 客户端搜索 | 用 [NVL](https://neo4j.com/docs/nvl/current/) / 力导向 + 点节点看属性 |
| Motif / Graphin(G6) + Neo4j | 调查分析 | 过滤面板 + 多种布局 | 过滤、分类型配色 |
| 国内高校/业务 KG 项目 | Vue + D3/ECharts | 搜索框 + 关系图 + 详情抽屉 | **中文业务场景最贴近**：左搜右图下表 |
| 美团等企业实践 | 自研图引擎 | 降噪、按需展开、叙事路径 | 大图必须**按需展开**，禁止全量渲染 |

### 2.2 结论：不直接「整站套用」开源探索器

| 选项 | 优点 | 缺点 | 建议 |
| --- | --- | --- | --- |
| 部署 AWS graph-explorer | 功能全 | 部署重、英文、对接我们 API/标签成本高、业务语义弱 | ❌ 不作主路径 |
| Neo4j Bloom | 体验好 | 许可/版本限制，仍是通用工具 | ❌ 可选给分析人员 |
| **自研轻量业务前端** | 中文、贴合「按专业查」、接现有 API、可控 | 需开发 1～2 周 | ✅ **主推** |

自研复杂度可控：后端子图接口已有，前端主要是「搜索 + 画图 + 详情」。

## 3. 推荐产品形态（用户怎么用）

### 3.1 一屏布局（中文）

```
┌─────────────────────────────────────────────────────────┐
│  职业教育知识图谱                    [国内|欧盟|美国]    │
├──────────────┬──────────────────────────────────────────┤
│ 🔍 搜索专业   │                                          │
│ [人工智能___] │            力导向 / 分层图谱画布          │
│ [查图谱]      │         （圆点=实体，线=关系）            │
│              │                                          │
│ 热门专业快捷  │                                          │
│ · 人工智能    │                                          │
│ · 计算机…     │                                          │
│              ├──────────────────────────────────────────┤
│ 图例          │  节点详情：名称 / 类型 / 来源链接 / 说明   │
│ 🔵专业 🔴岗位 │  [在官方页打开]                            │
│ 🟢技能 🟣课程 │                                          │
└──────────────┴──────────────────────────────────────────┘
```

### 3.2 核心交互（零代码）

1. **搜**：输入「人工智能」或点热门标签 → 调 `by-major`  
2. **看**：中间自动出图（默认展开 2 跳：专业→岗位→技能）  
3. **点**：点圆点 → 右侧详情（中文标签 + 来源链接）  
4. **扩**（可选）：详情里「展开关联」再拉一层邻居  
5. **滤**：勾选「只看岗位 / 只看技能」、地区切换  
6. **表**（可选）：底部表格列出「培养岗位」「所需技能」便于导出感

**禁止**在用户界面暴露 Cypher、Bolt 地址、节点 gid（可折叠在「高级」）。

### 3.3 中文映射

| 内部 type | 界面展示 |
| --- | --- |
| major | 专业 |
| occupation | 岗位 |
| skill_level | 技能等级 |
| course | 课程 |
| credential | 认证 |
| prepares_for | 培养对口 |
| requires | 岗位要求 |
| taught_by | 课程覆盖 |
| related_to | 相关 |

## 4. 技术架构（推荐）

```
浏览器  frontend/（静态或 Vite）
    │  HTTP JSON
    ▼
FastAPI  pipelines/api  （已有，可小扩）
    │  Bolt
    ▼
Neo4j
```

### 4.1 前端技术选型

| 层级 | 推荐 | 理由 |
| --- | --- | --- |
| 框架 | **Vue 3 + Vite** 或 **纯 HTML + 少量 JS** | 团队若偏简单：可先单页 HTML；要组件化用 Vue |
| 图渲染 | **AntV G6 5** 或 **ECharts graph** 或 **relation-graph** | 中文文档好、社区案例多；ECharts 上手最快 |
| 备选 | `@neo4j-nvl/react` / `react-force-graph` | 若坚持 React 生态 |
| UI | Element Plus / Naive UI / 自写 Tailwind | 搜索框、抽屉、标签 |

**MVP 建议：Vue3 + Vite + ECharts graph（或 G6）+ 调现有 FastAPI。**  
ECharts 关系图足够做「按专业子图」；节点过千再换 G6 做按需展开。

### 4.2 后端只需小改（不必重写）

已有：

- `GET /v1/graph/by-major?name=&region=&depth=&max_nodes=`
- `GET /v1/search?q=`
- `GET /v1/stats`
- `GET /v1/occupation/requires?q=`

建议增量：

| 接口 | 用途 |
| --- | --- |
| `GET /v1/majors/hot` | 热门专业列表（种子 + 统计） |
| `GET /v1/graph/neighbors?id=&types=` | 点节点「展开一层」 |
| 响应字段 `label_zh` | 后端直接给中文类型名，前端少映射 |

### 4.3 性能与安全规则

- 默认 `depth=2`，`max_nodes=150～300`  
- 不向前端暴露 Neo4j 密码；**只走 API**  
- 大图边超过阈值时 API 返回 `truncated: true`，UI 提示「已截断，请缩小范围」  
- CORS 已开，前端可独立端口（如 5173）

## 5. 不做 / 缓做

| 项 | 原因 |
| --- | --- |
| 直接给业务用户 Neo4j Browser | 英文 + 代码，体验差 |
| 首屏渲染全库 7 万边 | 浏览器卡死 |
| 一上来 3D 图谱 | 炫但难用，非刚需 |
| 嵌入 Bloom | 许可与部署复杂 |
| 前端直连 Bolt | 密码泄露风险 |

## 10. 不必拘泥于「蜘蛛网」图谱——更适合人类看的形态

力导向网状图（节点乱飘、线交叉）适合**分析师探查**，不适合**普通人理解职业路径**。教育/职业场景业界更常用「路径 + 分层 + 列表」。

### 10.1 形态对比（按「好不好懂」排序）

| 形态 | 长什么样 | 适合谁 | 优点 | 缺点 |
| --- | --- | --- | --- | --- |
| **① 分层泳道 / 漏斗列** | 左→右四列：专业 → 岗位 → 技能 → 课程/认证 | 业务默认主视图 | 结构清晰、像办事流程图 | 交叉关系弱化 |
| **② 路径卡片（学习路径）** | 步骤条：第1步选方向 → 第2步目标岗 → 第3步补技能 → 第4步课/证 | 学生/家长 | 叙事强、最像产品 | 一次只讲一条主路径 |
| **③ 表格 + 分组列表** | 「对口岗位表」「技能清单（L1–L4）」「推荐课」 | 教务/汇报 | 可扫读、可导出 | 关系不直观 |
| **④ 树形 / 思维导图** | 专业为根，岗位为枝，技能为叶 | 快速扫结构 | 熟悉、无交叉线 | 共享节点要重复出现 |
| **⑤ 桑基图 Sankey** | 流量带：专业→岗位→技能 | 展示「规模/权重」 | 主次分明 | 节点多时仍挤 |
| **⑥ 网状力导向** | 圆点连线乱飘 | 开发/图谱专家 | 发现意外关联 | **默认不要给普通用户** |

### 10.2 推荐产品结构（主次分明）

**默认主界面：不做蜘蛛网，做「查专业 → 看分层结果」。**

```
输入专业 [人工智能]  [查询]

┌─────────┬──────────────┬──────────────┬──────────────┐
│ 本专业   │ 对口岗位      │ 关键技能       │ 课程 / 认证   │
│ 人工智能 │ · AI算法工程师│ · Python L2  │ · 吴恩达ML   │
│ 简介…   │ · NLP工程师   │ · 深度学习 L3│ · 1+X …     │
│         │ · 大模型开发  │ · …          │              │
└─────────┴──────────────┴──────────────┴──────────────┘
 点击「AI算法工程师」→ 下方展开该岗位技能等级表 + 推荐课
```

可选增强（二次点击再出）：

- **「查看关系简图」**：用**分层有向图**（专业在上、岗位中、技能下，线不交叉乱排），不要力导向。  
- **「生成一条培养路径」**：路径卡片 / 时间线（适合 toC）。  
- **「对比两个岗位」**：技能差异表（适合转岗）。

### 10.3 和数据模型怎么对应

五维关系不变，只是**投影方式**不同：

| 用户看到的块 | 图上的跳 |
| --- | --- |
| 对口岗位列 | major `-[:PREPARES_FOR]->` occupation |
| 技能列 | occupation `-[:REQUIRES]->` skill_level（可按 L 聚合） |
| 课程/认证列 | skill `-[:TAUGHT_BY]->` course，或 occupation→credential |

API 仍可用 `by-major`，前端按 `type` 分桶渲染列，而不是把所有点丢进一张网。

### 10.4 交互原则（更「人类」）

1. **先列表，后连线**——扫得懂再给图。  
2. **一次只突出一条路径**——点选岗位后高亮「专业→该岗→技能→课」。  
3. **等级用标签不是用线缠**——L1/L2/L3/L4 用色点或徽章。  
4. **来源放详情里**——「数据来自 O\*NET」链出去，不挡主阅读。  
5. **网状图放「高级/探索」折叠面板**，默认收起。

### 10.5  rev 技术选型（随形态调整）

| 视图 | 实现 |
| --- | --- |
| 四列泳道 + 卡片 | Vue/HTML + CSS Grid，**几乎不用图库** |
| 路径步骤条 | 普通 Steps 组件 |
| 分层关系简图 | ECharts `graph` + `layout: 'none'` 固定分层坐标，或 G6 dagre |
| 桑基 | ECharts sankey |
| 表格 | Element Plus Table |

MVP 甚至可以**零图库**：搜索 + 四列卡片 + 岗位下钻表格，上线最快、最好懂。

## 11. 建议拍板项

1. **做自研中文前端**（不套 graph-explorer / Bloom 给业务用户）  
2. **默认视图：分层列 + 卡片/列表，而不是网状图谱**  
3. **网状图仅作「高级探索」可选项**  
4. **技术栈：Vue3 + Vite +（主界面 CSS 卡片）+ 可选 ECharts 分层图；接现有 FastAPI**  
5. **MVP 交互：搜专业 → 四列结果 → 点岗位看技能/课**  

确认后按此实现 `frontend/`。
