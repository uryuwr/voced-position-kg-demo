## 3. 主要不足（按优先级）

### P0 — 结构空洞（影响「五维贯通」叙事）

1. **岗→技极稀疏**  
   - 大典 1639 岗，有 requires 的约 **13** 岗。  
   - 根因：国家技能标准**无统一开放全量清单**，现仅 14 PDF。

2. **可学资源过少**  
   - 课目标 1.6 万 vs 可点开学的资源 **~30**。  
   - 智慧职教公开接口仅为首页精选；全量列表/反爬限制。

3. **约 40% 专业无专→岗**  
   - 无对应课标 PDF、或职业面向码匹配失败、或关键词未命中。  
   - 普通本科大量专业与大典对口弱，属预期缺口。

4. **约 60% 专业无专→课**  
   - 课标只覆盖有 PDF 的专业层次/代码；普通本科多数无本库课标。

### P1 — 数据质量与可信度

5. **AI/规则边占比高、未人工抽检**  
   - prepares_for / 证书挂边 / 课→技 大量 `ai_inferred` + `review_status=pending`。  
   - 噪声风险：同名关键词误连、证书关键词过宽。

6. **课目标解析噪声**  
   - PDF 抽取偶发脏课名（截断、页眉页脚混入）。

7. **技能节点粒度不均**  
   - 工种五级制 vs 工程技术人员初级/中级/高级；解析策略启发式，功能名可能偏碎或偏粗。

8. **认证无官方「考什么证」对照**  
   - 现为名称关键词，不能当招生/报考权威依据。

### P2 — 产品与工程

9. **EU/US 与 CN 混库**  
   - requires 全局以 O*NET/ESCO 为主；Admin 需始终带 region=CN，避免「边很多但都不是国内」。

10. **Graph 仍不适合当「全量目录」**  
    - 应用 Table 做目录；Graph 做关系子图（已改默认行为，需用户习惯）。

11. **缺少持续质量监控**  
    - 覆盖率报告有；缺定期回归（坏边率、孤儿节点率、样例路径冒烟）。
