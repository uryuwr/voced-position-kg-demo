# 从需求本质看：展示形态 + 应届生 / 教师路径

## 1. 需求本质（不是「画一张图」）

系统背后的五维是：

**专业 → 岗位 → 技能等级 → 课程 → 认证**

用户真正要完成的任务只有两类：

| 任务 | 核心问题 | 成功长什么样 |
| --- | --- | --- |
| **职业规划** | 我（或学生）适合/能去哪些岗？差距是什么？ | 选中 1～2 个目标岗 + 说得出「为什么」 |
| **学习计划** | 先补什么、学什么课、考什么证、什么顺序？ | 一份可执行的阶段计划（周/月） |

因此：

- **图数据库**负责存关系、给 AI/规则算路径。  
- **界面**负责完成上述两个任务，而不是展示「我们有图谱」。  

**结论：主界面应是「目标岗档案 + 技能差距 + 分阶段学习计划」；关系简图/网状图最多作辅助。**

推荐主形态（按优先级）：

1. **岗位档案页**（My Next Move 范式）— 任务、技能等级、相关课/证  
2. **学习路径时间线**（分阶段计划）— 由技能缺口生成  
3. **专业看板**（给教师）— 一专业多学生/多出口对比  
4. 分层关系小图 — 可选「看看关系」  
5. 力导向全图 — 仅运维/专家

## 2. 假设：我是应届生，怎么用这套系统做规划与计划

### 2.1 我的状态

- 刚毕业或大四，专业固定（如「软件技术」「人工智能」）。  
- 不清楚岗、不清楚差什么、需要「下一步干什么」。  

### 2.2 理想使用路径（产品应引导）

```text
① 选身份：应届生 / 在校
② 确认专业（或从教育部专业名搜索）
③ 系统给出「本专业常见出口岗位」Top N（可按热度/薪资/匹配度）
④ 我点 1～2 个目标岗 → 进入「岗位档案」
⑤ 系统对照技能等级：已会 / 薄弱 / 缺失（可自评或测评）
⑥ 一键生成「90 天学习计划」：课 + 证 + 顺序
⑦ 收藏计划，按周打卡（后续可接 Agent 陪伴）
```

### 2.3 每一步对应五维与界面

| 步骤 | 用到的维 | 界面应长什么样 |
| --- | --- | --- |
| 确认专业 | 专业 | 搜索/确认一张「专业卡」 |
| 选出口 | 专业→岗位 | **岗位卡片列表**（不是网） |
| 看清岗位 | 岗位 | **档案页**：职责、门槛、发展 |
| 看清差距 | 岗位→技能等级 | **技能表 + L1–L4 + 缺口高亮** |
| 定计划 | 技能→课程、技能/岗→认证 | **时间线：第1月…第3月** 课与证分开 |
| 执行 | — | 清单/打卡，而非继续看图 |

### 2.4 应届生视角：什么叫好用

- 3 分钟内能选出目标岗。  
- 能说清「我缺 Python·L2、算法·L2」。  
- 计划是「本周看哪门课、何时考什么证」，不是「再点开一个节点」。  

**应届生几乎不会去「探索全图」**；他要的是**收敛**：一个方向 + 一份计划。

## 3. 假设：我是大学教师，怎么用系统帮不同专业学生

### 3.1 我的状态

- 带多个专业/班级，要就业率、对口率、培养方案自洽。  
- 需要**批量、可解释、可对标政策**（岗课赛证、红黄牌、产业匹配）。  

### 3.2 理想使用路径

```text
① 选「教师/教务」视图
② 选专业（可切换多个专业）
③ 看「专业出口看板」：主岗位群、次岗位群、技能覆盖热力
④ 发现缺口：培养方案覆盖弱的技能 / 缺失认证出口
⑤ 为学生或班级生成「推荐路径包」（2～3 条职业轨道）
⑥ 导出：岗位列表、技能矩阵、推荐课证、给辅导员的话术
⑦ （进阶）对接产业 Gap：某区域岗位需求 vs 本校培养
```

### 3.3 教师与应届生界面差异

| | 应届生 | 教师 |
| --- | --- | --- |
| 粒度 | 个人 1 条主路径 | 专业级 + 可下钻个人 |
| 默认页 | 我的目标岗 + 我的计划 | **专业出口看板 + 技能覆盖** |
| 关键操作 | 选岗、生成计划 | 换专业对比、找培养缺口、批量推荐 |
| 课/证 | 个人学习清单 | 课证是否支撑岗位（矩阵） |
| 成功标准 | 找到方向并开干 | 班/专业路径清晰、材料可汇报 |

### 3.4 教师路径里五维怎么用

| 教师问题 | 五维用法 | 展示 |
| --- | --- | --- |
| 这专业学生能去哪？ | 专业→岗位 | 出口岗位表（占比/层级） |
| 课是否支撑岗？ | 岗→技能，课→技能 | **矩阵：技能 × 课程覆盖** |
| 缺什么证？ | 岗/技能→认证 | 认证清单 + 与岗映射 |
| 给不同学生不同建议 | 同一专业多轨道 | 轨道 A/B/C（开发 / 运维 / 产品…） |
| 和产业是否脱节 | 岗位技能 vs 方案 | Gap 列表（对接方案里的产业-人才分析） |

教师要的是**可讲解、可导出**，不是自己在网里点着玩。

## 4. 综合：哪种展示形式更好？

从需求本质出发：

| 形态 | 应届生 | 教师 | 总评 |
| --- | --- | --- | --- |
| 力导向网 | 差 | 差 | 不作主界面 |
| 五列管理台 | 一般 | 一般 | 像后台，不像完成任务 |
| **岗位档案 + 技能表** | **优** | 优（下钻） | **主界面首选** |
| **分阶段学习计划时间线** | **优** | 优（模板） | **规划交付物** |
| **专业出口看板 + 覆盖矩阵** | 弱 | **优** | **教师主界面** |
| roadmap 技能树 | 良（偏学） | 中 | 适合「学」阶段 |
| 分层关系小图 | 中 | 中 | 辅助解释「为何相关」 |

### 产品信息架构建议

```text
角色分流
├── 应届生/学生
│     首页：搜/确认专业 → 推荐岗位
│     岗位页：档案 + 技能差距
│     计划页：90 天课+证时间线（课、证分开展示）
│
└── 教师/教务
      首页：选专业 → 出口岗位 + 技能覆盖概览
      缺口：未覆盖技能 / 薄弱认证
      发放：给学生的路径包 / 导出
```

同一套 Neo4j 查询；**两套皮肤、同一五维**。

## 5. 端到端故事（验收用）

### 应届生小李（人工智能专业）

1. 选「应届生」→ 专业「人工智能」。  
2. 系统推荐：算法工程师、大模型应用开发、数据分析…  
3. 点「大模型应用开发」→ 看到技能：Python·L2、RAG·L3、Prompt·L2…  
4. 自评后缺口高亮。  
5. 生成计划：第 1–2 周 Python 课；第 3–6 周 RAG 项目课；第 7–8 周某认证/作品集。  
6. 完成标准：收藏计划 + 知道本周第一件事。

### 教师王老师（带软件 + 大数据两个专业）

1. 选「教师」→ 专业「软件技术」。  
2. 看板：出口以开发/测试/运维为主；某技能覆盖率为 0。  
3. 切换「大数据」对比出口差异。  
4. 为毕业班导出 3 条轨道说明，发给辅导员。  
5. 完成标准：能在 10 分钟内讲清「本专业主出口 + 课证支撑 + 缺口」。

---

## 6. 一句话

- **更好的展示形式** = **学生侧岗位档案与学习计划** + **教师侧专业出口与覆盖矩阵**；不是网状图，也不是五列永远平铺。  
- **应届生**：收敛到目标岗 → 技能差距 → 可执行课证计划。  
- **教师**：看清专业出口与培养缺口 → 为学生批量化路径 → 可解释可导出。  

图在底下；**脸上是「规划工作台」**。
